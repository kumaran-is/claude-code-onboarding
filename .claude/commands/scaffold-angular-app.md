# Scaffold Angular SPA (CLI-first)

**Arguments:** $ARGUMENTS — app name (default `my-app`; the first argument that is not a flag) and an
optional `--ui=daisyui|spartan|hybrid` (`--ui=none`: the legacy opt-out, Angular without Tailwind or a UI
library). Mode guide, setup details and component ownership: `angular-spa/reference/ui-mode-selection.md`.

**Rule:** the Angular CLI creates every boilerplate file (workspace, components, services, guards,
interceptors, interfaces, environments, libraries, integrations). Claude writes code by hand only
for application logic the CLI cannot know: auth behaviour, the error model, feature states and
tests of that behaviour. Never hand-write `angular.json`, `main.ts`, `app.config.ts` from nothing,
`tsconfig*.json` or a component/service skeleton the CLI can generate.

## Three cases — pick one before running anything

| Case | When | What runs |
|---|---|---|
| **A. New workspace** (this command) | No Angular workspace at the target path | Steps 1–12 below |
| **B. Feature in an existing workspace** | `angular.json` exists | Skip steps 1–4. Run `angular-ui-mode.sh detect <dir>` and keep its mode (no question; a missing record in a Tailwind + UI-library workspace is written with `npm pkg set config.uiMode=<detected>`). Use the workspace's own CLI (`npm exec --no -- ng …`; never a global or `npx @latest` CLI) for `ng generate`, then the custom steps. Process: `angular-spa` skill `SKILL.md` |
| **C. Existing project on an older major** | `@angular/core` < 22 | Do not scaffold over it. Upgrade: commit or stash first, then `npm exec --no -- ng update @angular/core@22 @angular/cli@22` (one major at a time; read angular.dev/update-guide). Then the opt-in migrations, each with `--dry-run` first: `ng generate @angular/core:service-migration` (Injectable → Service; alias `@angular/core:service`), `@angular/core:inject-migration`, `@angular/core:control-flow-migration`, `@angular/core:signal-input-migration`, `@angular/core:output-migration`, `@angular/core:signal-queries-migration`, `@angular/core:common-to-standalone-migration`, `@angular/core:ngclass-to-class-migration`, `@angular/core:ngstyle-to-style-migration`. List them with `ng generate @angular/core: --help` |

**Never overwrite an existing project.** Before step 1, check that the target directory does not
exist or is empty (`ls -A <name>`). If it contains files, STOP and ask; do not pass `--force`.

## Step 0 — UI mode (before anything is generated)

```bash
bash .claude/scripts/angular-ui-mode.sh resolve --args "$ARGUMENTS" --project <target dir>; echo "exit=$?"
```

- `MODE=<m>` → use it; do not ask. `SOURCE=project` means the target is an existing workspace: this is
  case B, keep its mode.
- `ACTION=ask` → ask **one** question with the AskUserQuestion tool, exactly as in
  `ui-mode-selection.md` §2 (daisyUI first and marked Recommended, then Spartan UI, then Hybrid; one line
  each on what it is best for). If the user asks for more information, recommend from §1 with a one-line
  reason and ask the same question again. Never assume daisyUI in an interactive session.
- No AskUserQuestion tool (headless `claude -p`, CI) → re-run with `--noninteractive`: `MODE=daisyui`,
  and the summary says it was defaulted.
- Exit 2 (invalid mode) or 3 (conflicts with the existing project's mode) → show the message and stop.

Keep the chosen mode for every later step, test and the summary. Do not ask again.

## Steps

All `ng` commands after step 1 run inside the new workspace with its local CLI:
`npm exec --no -- ng <command> … --defaults --interactive=false`, and each is followed by `echo "exit=$?"`.
A non-zero exit is a failed step: report it, fix the cause, never continue as if it succeeded.

### CLI-generated scaffolding

1. **Create the workspace** (the `CC_SCAFFOLD=` prefix is the per-command authorization
   `block-raw-scaffold.sh` requires):
   `CC_SCAFFOLD=scaffold-angular-app npx @angular/cli@22.3.0 new <name> --style=css --ssr=false --skip-git --defaults`
   This produces a zoneless, standalone app with Vitest + jsdom, `provideBrowserGlobalErrorListeners()`,
   the 2025 file-name style (`app.ts`, no `.component` suffix) and no lint target. Other verified
   `ng new` 22.3 options: `--ssr` (only when the user asks for SSR), `--zoneless`, `--routing`,
   `--prefix`, `--package-manager`, `--file-name-style-guide 2016|2025`, `--ai-config` (for example
   `claude-code`), `--strict` (default `true`). `--test-runner` is deprecated (Vitest only in a future version).
2. **Tighten Angular ranges** — in `package.json` change every `"@angular/…": "^22.…"` to `"~22.…"`, then `npm install`.
   Record the mode: `npm pkg set config.uiMode=<mode>`.
3. **Integrations with `ng add`:**
   - Lint: `npm exec --no -- ng add angular-eslint@22.8.0 --skip-confirmation` (adds the `lint` target).
   - Tailwind (every mode except `none`): `npm exec --no -- ng add tailwindcss --skip-confirmation`
     (CLI built-in action: creates `.postcssrc.json`, adds `@import 'tailwindcss';`, installs caret ranges), then
     pin: `npm install --save-exact tailwindcss@4.3.5 @tailwindcss/postcss@4.3.5 postcss@8.5.33`.
   - UI library, by mode (exact commands, generator quirks and post-generation edits:
     `ui-mode-selection.md` §3; never install a library the mode does not name):
     - `daisyui`: `npm install --save-exact daisyui@5.8.2`; `src/styles.css` from `daisyui-v5-components.md`
       (themes, `@plugin "daisyui/theme"` override, `@theme` tokens).
     - `spartan`: `@spartan-ng/cli@1.10.1`, `ng g @spartan-ng/cli:init --theme=neutral` once,
       `components.json` written before the first `ui` run, one `ng g @spartan-ng/cli:ui <name>` per
       component the app uses, pins, the 44 px / contrast edits to the copied Helm, lint for `libs/ui/**`,
       then uninstall the CLI.
     - `hybrid`: the daisyUI step, then the Spartan steps for Spartan-owned components only (dialog,
       dropdown-menu, popover, select/combobox and their dependencies), then the hybrid stylesheet and token
       mapping from §6 (never set `--border`), the deferred account menu and the 550 kB initial warning budget.
     Details: `reference/tailwind-v4-config.md`.
   - No state library, SSR or component library is added unless the user asks (then `ng add @angular/ssr`,
     `ng add @angular/material`, …, pinned to `@22.3.0`).
4. **Generate the structure** — folders come from the generated files' paths (22.3 has no `--path`
   option; put the path in the name):
   ```bash
   npm exec --no -- ng generate environments                                   # environment.ts + .development.ts, fileReplacements
   npm exec --no -- ng generate interface core/http/api-error
   npm exec --no -- ng generate service core/auth/auth-session                 # emits @Service() (22.3 default)
   npm exec --no -- ng generate service core/logging/logger
   npm exec --no -- ng generate interceptor core/http/auth                     # functional HttpInterceptorFn (default)
   npm exec --no -- ng generate guard core/auth/signed-in --implements CanActivate   # functional CanActivateFn (default)
   npm exec --no -- ng generate service features/dashboard/dashboard-api
   npm exec --no -- ng generate component features/dashboard/dashboard-page
   npm exec --no -- ng generate component features/auth/sign-in-page
   npm exec --no -- ng generate component features/not-found/not-found-page
   ```
   Generated conventions (22.3): `dashboard-page.ts/.html/.css/.spec.ts` in its own folder, class `DashboardPage`;
   no `standalone` and no `changeDetection` property (`--change-detection` defaults to `OnPush`, the v22
   default; never pass `Eager` without a reason); services use `@Service()` (`--injectable` would emit the
   old `@Injectable`; do not use it for new singletons); guards/interceptors are functions
   (`signed-in-guard.ts`, `auth-interceptor.ts`). A shared library, only when asked:
   `npm exec --no -- ng generate library <name>` (adds `projects/<name>`, a tsconfig path, its own eslint config).

### Custom application code (only what the CLI cannot generate)

The generated guard (`return true`), interceptor (`next(req)`), empty interface and empty
environments are placeholders; `ng lint` fails on the guard's unused parameters and the empty
interface. Replace every placeholder before step 12 — never ship them.

5. **`app.config.ts`** (edit the generated file): keep `provideBrowserGlobalErrorListeners()`; use
   `provideRouter(routes, withComponentInputBinding())`; add `provideHttpClient(withInterceptors([authInterceptor]))`
   only because there is an interceptor (HttpClient itself needs no provider in v22; never `withFetch()`,
   it is deprecated and fetch is the default); an `API_CONFIG` provider with the API origin(s) allowed to
   receive credentials. No zone provider.
6. **Auth** — fill the generated `authInterceptor` (allow-listed origins only, single-flight refresh, one retry,
   no refresh on 403), `AuthSession` (in-memory token, HttpOnly refresh cookie), `signedInGuard`
   (waits for session restore, returns a `UrlTree` to sign-in with a safe `returnUrl`) from
   `reference/web-security.md`. No tokens in `localStorage`. Comment that guards are UX and the API authorizes.
7. **Typed error model + logger** — fill `core/http/api-error.ts` (`ApiError`, `toApiError`) and
   `core/logging/logger.ts` from `angular-ui-patterns/reference/error-handling.md`. No `console.*` elsewhere.
8. **Dashboard feature** — components from the mode's owner (`ui-mode-selection.md` §4). Fill `DashboardApi` (typed, errors propagate) and `DashboardPage`, which reads it
   with `rxResource` or `httpResource` (stable in v22; read `value()` only after `hasValue()`) and renders **four states**:
   loading (`role="status"`), empty, error (`role="alert"`, message from `ApiError.kind`, retry except for
   401/403) and success. When the backend is absent the page shows the **error state with retry** —
   never fallback, static or mock data. Under `ng serve` an absent `/api/*` answers `GET` with
   `index.html` (200, `text/html`), so the UI error is a JSON parse failure (`HttpErrorResponse` status 200), not
   a 404: unit tests drive 403/5xx/status 0 with `HttpTestingController`, and an E2E check against the real dev
   server asserts the error state and that Retry issues a new request.
9. **Shell and routes** — replace the `ng new` placeholder in `app.html` with the app shell (it ships a
   demo page with its own `<h1>`/`<main>` that breaks the heading structure); update `app.spec.ts` to match.
   Routes: lazy `loadComponent`, root redirect to `dashboard`, `canActivate: [signedInGuard]` on protected
   routes, `title` per route, the not-found page for `**`.
10. **Environment** — `environment.ts` / `environment.development.ts` hold only public values (API origin).
    They ship to every browser: no secrets.
11. **Tests** (`reference/testing-vitest.md`) — extend the generated specs: dashboard spec covering loading,
    empty, error (403 and 5xx) and success with `HttpTestingController` (flush before `whenStable()`);
    interceptor spec (no credentials to a look-alike host; one refresh for concurrent 401s; no loop); guard
    spec with `RouterTestingHarness`. No `fakeAsync`.

### Verify

12. Run each and report its own exit code:
    ```bash
    npm exec --no -- ng test --watch=false; echo "test exit=$?"
    npm exec --no -- ng build; echo "build exit=$?"
    npm exec --no -- ng lint; echo "lint exit=$?"
    npm exec --no -- tsc -p tsconfig.app.json --noEmit; echo "tsc app exit=$?"
    npm exec --no -- tsc -p tsconfig.spec.json --noEmit; echo "tsc spec exit=$?"
    # from the Claude project root (where .claude/ lives), not inside the app:
    bash .claude/scripts/angular-ui-mode.sh detect <name>; echo "ui-mode exit=$?"   # mode recorded and consistent
    npm audit --audit-level=high; echo "audit exit=$?"
    ```
    TypeScript 6 is strict by default (probe on 6.0.3: a file with an implicit `any` and a
    `null`→`string` assignment compiled with `tsc --ignoreConfig` exits 2 with TS7006/TS2322; with
    `--strict false`, exit 0). Writing `"strict": true` in `tsconfig.json` is optional, for clarity.
    `tsc` does not check templates; `ng build` does. Any non-zero exit → fix before finishing.
    E2E (recommended, required once the app has a real journey; triggers in `.claude/rules/web-frontend.md`):
    `npm i -D --save-exact @playwright/test@1.65.1 @axe-core/playwright@4.14.1`, `npx playwright install chromium`,
    then `playwright.config.ts` from `browser-testing/reference/playwright-test-suite.md` with
    `webServer.command: 'npm exec --no -- ng serve --port 4200'`; gitignore `playwright/.auth/` and `.playwright-cli/`.
    The same install gives Claude the Playwright CLI (`npx --no-install playwright cli`).
13. **Summary** — the UI mode and how it was chosen (flag, question, project, non-interactive default),
    which files the CLI and the Spartan generators produced vs which were hand-written (steps 5–11), the exit
    codes, how to run (`npm start`), next steps.
