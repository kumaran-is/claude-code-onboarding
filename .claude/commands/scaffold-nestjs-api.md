# Scaffold NestJS API

**Project name:** $ARGUMENTS (default to "my-nestjs-api" if not provided)

All file contents come from the `nestjs-api` skill, which was verified on NestJS 12.6.0 (Node 26.13.1, PostgreSQL 18, Redis 8).
The project is written from those templates rather than generated by `nest new` (`@nestjs/schematics` 12.0.16 template:
Express, caret ranges, `@types/node` 24, Vitest 4, oxlint with `no-explicit-any` off). Without a TTY, or with `CI` set,
`nest new` answers its prompts with defaults: it enables `@nestjs/observe` (a hosted, paid service) and runs an unpinned
`npx @nestjs/skills@latest add --agent all`, unless passed `--no-observe --skip-skills`. Do not run a project creator — the scaffold hook blocks it and it is not needed.

## Steps

1. **Create `.gitignore` first** — before any other file: `node_modules/`, `dist/`, `coverage/`, `reports/`, `src/generated/`, `.env`, `*.pem`, `*.key`, `.DS_Store`.
2. **Read the skill** — `nestjs-api/SKILL.md`, then `reference/nestjs-config-npm-ts.md` (versions, `package.json`, tsconfig, Vitest, oxlint) and `reference/nestjs-production-baseline.md` (source files, tests, Dockerfile, CI).
3. **Check versions** — for each pinned package, `npm view <pkg>@<major> version`. If a newer patch exists on the same major, use it; if a package is not found, stop and report it (never guess a package name). Keep every NestJS core package on one version; Prisma stays on the stable 7.x line while 8.x is a release candidate; TypeScript stays `6.0.x`.
4. **Write `package.json`** (`"type": "module"`) from `nestjs-config-npm-ts.md`, then `npm install` (lockfile committed). `ioredis` is a direct dependency (bullmq 6 needs it).
5. **Write config files** — `tsconfig.json`, `tsconfig.build.json`, `nest-cli.json`, `vitest.config.ts`, `vitest.config.e2e.ts`, `.oxlintrc.json`, `prisma.config.ts`, `prisma/schema.prisma`.
6. **Write source** from the baseline — `src/main.ts`, `src/configure-app.ts`, `src/app.module.ts`, `src/instrumentation.ts`, `src/config/env.ts`, `src/auth/*` (principal, token verifier, decorators, global guard), `src/common/throttler-tracker.ts`, `src/database/prisma.service.ts`, `src/health/health.controller.ts`, and one example feature (the baseline's `src/orders/` schemas, repository, service and controller) with a tenant-scoped repository. Relative imports end in `.js`. Required directories after this step: `src/config/`, `src/auth/`, `src/common/`, `src/database/`, `src/health/`.
7. **Write tests** — the unit specs and `test/app.e2e-spec.ts` from the baseline (they include the negative cases: 401, 403, cross-tenant 404, 400, 413, 429, no secret fields, schema-breaking response → 500).
8. **Infrastructure** — `Dockerfile` (multi-stage `node:26-alpine`, `USER node`) and `.github/workflows/ci.yml` from the baseline, `docker-compose.dev.yml` (PostgreSQL 18, Redis 8) from `reference/nestjs-templates-infrastructure.md`; `.env` written via **Bash** with local defaults matching docker-compose (no real secrets).
9. **Generate and verify** — start PostgreSQL and Redis (`docker compose -f docker-compose.dev.yml up -d`), then run each and quote its exit code; any non-zero exit stops the scaffold:
   - `npx prisma generate`
   - `npx prisma migrate dev --name init`
   - `npm run typecheck`
   - `npm run lint`
   - `npx vitest run --reporter=default --reporter=json --outputFile=reports/unit.json` (executed count > 0)
   - `npm run test:e2e -- --reporter=default --reporter=json --outputFile=reports/e2e.json` (executed count > 0)
   - `npm run build`
   - `npm audit --audit-level=high` (fix, or document an `overrides` entry with the advisory id)
10. **Report** — files created, each command with its exit code and test counts, and anything NOT RUN (for example no Docker daemon: PostgreSQL/Redis tests and the image build are BLOCKED, not passed).
