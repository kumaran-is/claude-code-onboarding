# NEXUS Orchestration and State Template

NEXUS coordinates a feature that is too large for one SDD run: 10+ tasks, several domains (backend, frontend/mobile, infra, security) and several sessions. It chains six gated phases; Phase 4 runs one SDD pipeline per PR slice. A state file at `docs/nexus-state/<feature>.md` (template below) carries context between sessions.

| Signal | Use |
|--------|-----|
| <= 10 tasks, one domain, one session | Plain SDD (`../SKILL.md`) |
| 10+ tasks, several domains, multi-day | NEXUS |

**Rule:** never start Phase 4 without an approved spec (Phase 1) and approved API contracts (Phase 2). Implementing against a moving spec forces rewrites in every layer.

## Phases and Go/No-Go Gates

Every gate is blocking. Update the state file at each gate crossing.

| # | Phase | Run | Gate |
|---|-------|-----|------|
| 1 | Spec | `feature-forge` skill (EARS spec, NFRs, out-of-scope list) | Human approved the spec; no open questions; state file created |
| 2 | Architecture | `/design-architecture` (`architect` agent): C4 diagrams, sequence diagrams, API contracts (shapes + error codes), one ADR per key choice (`architecture-decision-records` skill); then `plan-challenger` | Contracts approved; no unresolved plan-challenger **Blocker**; each **Concern** fixed or accepted in writing |
| 3 | Database (skip if no schema change) | `/design-database` (`database-designer`); migrations in the stack's tool (Alembic, Flyway or Prisma), each reversible; indexes checked with `EXPLAIN ANALYZE` | `postgresql-database-reviewer` verdict SAFE TO APPLY; no table drop without explicit human approval |
| 4 | Implementation | Per slice: `/plan-review` → `docs/plans/YYYY-MM-DD-<feature>.md` → SDD pipeline (implementer → spec reviewer → quality reviewer) → PR | All TaskList tasks completed; no BLOCK verdict; every NEEDS_REVIEW (HIGH) fixed or justified in writing in the PR |
| 5 | Security | `/audit-security` (it already runs `/security-dependencies`; do not run it again), plus `/security-sast` and `/xss-scan` when the scope needs them (see the scope table in `/audit-security`). Add `threat-modeling-expert` for a new attack surface and `flutter-security-expert` for mobile | Zero unresolved CRITICAL; each HIGH fixed or accepted with written human sign-off (and an ADR if it changes a design decision); Lock Document written |
| 6 | Deploy | `/ship`; pipeline and rollout per `.claude/skills/deployment-ci-cd/SKILL.md` (`deployment-engineer`); infrastructure via `terraform-skill` (`terraform-specialist`) | `/ship` returns READY TO SHIP; staging health check green before production; error rate and latency watched for 30 min after the production deploy. Then close the state file |

## PR Slicing (Phase 4)

Never ship a 10+ task feature as one PR. Each slice gets its own SDD run and its own PR (`/create-pr`); record merges in the state file.

| Slice | Contents | Ship when |
|-------|----------|-----------|
| 1 Data model | Migrations, seed data, model types | Phase 3 gate passed |
| 2 Backend API | Endpoints, services, unit tests | API contract fully implemented |
| 3 Frontend / mobile | UI, state management, integration tests | Slice 2 merged |
| 4 Integrations + E2E | Third-party integrations, E2E suite, observability | Slice 3 merged |

Slices 2-4 may run in parallel only when they share no dependency; coordinate with TaskList (and TeamCreate for parallel teams).

## Session Resume

At the start of every session on an active NEXUS feature:

1. Run TaskList: current phase and last completed task.
2. Read the plan file: task list and acceptance criteria.
3. Read the state file: phase, open decisions, deferred items.
4. Check the recent git log: committed vs still in progress.
5. Resume at the next incomplete task of the current phase.
